## 2. The review's headline finding was wrong — and finding that out is the result

The review called negative rejection the #1 weakness: 20/40 unrelated
queries could still receive a `source="knowledge_base"` answer.

**Root cause of the confusion:** `per_category_breakdown()` did not take
the `apply_coverage_gate` argument that `evaluate_threshold()` did. So
the per-category table was scored on similarity ALONE while the
precision/recall/F1 headline printed beside it was scored WITH the
coverage gate. Two different systems in one table.

Measured, with the gate the system actually ships:

| | Exact | Paraphrase | Negative rejected |
|---|---|---|---|
| Similarity only | 15/15 | 11/15 | 20/40 |
| **Shipped (gated)** | **15/15** | **4/15** | **37/40** |

Negative rejection is 92.5%, not a coin flip. **Paraphrase recall at
4/15 is the actual weakness**, and it is the price the coverage gate
pays for that precision.

Changed:
- `per_category_breakdown()` now takes `apply_coverage_gate`, defaulting
  to `True` to match `evaluate_threshold()`.
- The existing test that pinned the ungated trade-off now passes
  `apply_coverage_gate=False` explicitly — it is a legitimate
  measurement (it is the argument for the gate existing), it just had to
  say which system it measured.
- New `test_shipped_pipeline_trades_paraphrase_recall_for_precision`
  pins the deployed behaviour separately.

## 3. Tuning is exhausted — new evidence, `sweep_gates.py`

The threshold had been swept; the coverage gate was fixed at 0.7 by hand
and never swept. Sweeping both together, 24 combinations:

**F1 varies by only 0.128 across the entire grid, and the shipped
configuration is already the global best.** The two gates trade against
each other rather than compounding — every setting that recovers
paraphrase recall gives back an equal amount of negative rejection.

This is the evidence that closing the paraphrase gap needs a different
*representation*, not a different constant. It also pre-empts the
obvious objection that 4/15 is just a badly chosen threshold.

---

## 4. The coverage gate must not be carried into the dense backend unchanged

`query_coverage` exists because a TF-IDF vectorizer silently drops
out-of-vocabulary terms — "minimum wage in south africa" gets scored as
if it said "south africa". Sentence-transformers subword-tokenize and do
not drop unknown words, so the failure the gate was built for does not
arise there. Keeping `min_coverage = 0.7` in the dense path would import
a TF-IDF workaround into a backend that does not need it and suppress
paraphrase recall for no reason.

`sweep_gates.py --semantic` re-sweeps per backend. The gate is a
hyperparameter of the backend, not a constant of the system.

---

## 5. `match_margin()` — abstention signal for the dense path

Dense similarities are compressed (unrelated pairs sit well above zero),
so an absolute threshold tuned for TF-IDF transfers badly. The gap
between best and second-best match is scale-independent.

Added to `KnowledgeRetriever`, built on the existing `top_k`.
Deliberately **not** wired into `query_fact` — which of similarity,
coverage and margin should gate the answer is what the backend
comparison is meant to decide, and hard-coding it now would prejudge the
experiment.

## 6. Documentation drift — fixed, and the guard widened

`test_no_document_states_a_stale_row_count` used
`\b(\d+)\s*(?:rows|entries)\b`, which missed two forms that had already
shipped: `"32-entry dataset"` (hyphenated, singular) and
`"rows evaluated: 32"` (count follows the noun).

Regex widened to catch both. **It immediately found a third stale count
the review had not spotted, in `docs/ARCHITECTURE.md` ("32-row
corpus").** All three corrected.

The README retrieval section has been rewritten to present both systems
explicitly rather than conflating them, and `evaluate.py` now emits the
corrected gated per-category numbers.

## Not done, and why

- **Hybrid BM25 + dense + reranker + 5-level confidence.** A semester,
  not sixteen days.
- **KB expansion to 300–1,000 sourced records.** Right long-term. Cannot
  be curated and source-verified at that volume in the time available,
  and unsourced bulk would undercut the provenance argument.
- **Intent routing, query resolution, calibration, adversarial suite.**
  All correct, all Tier 2, each a new failure surface this close to the
  deadline.
- **The dense comparison itself.** `compare_retrievers.py` and
  `sweep_gates.py --semantic` are both ready to run, but Hugging Face is
  not reachable from this environment, so the weights could not be
  downloaded. This is the one experiment left, and it now has a precise
  hypothesis: **lift paraphrase above 4/15 without dropping negatives
  below 37/40.** Run it in a separate virtualenv — `sentence-transformers`
  pulls in torch, which has already segfaulted against this project's
  TensorFlow install.
